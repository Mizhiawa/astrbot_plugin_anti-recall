# astrbot_plugin_anti_recall

防撤回查询插件（AstrBot + NapCat / aiocqhttp）。

机器人平时会把收到的消息缓存在内存里；当某条消息被撤回时，插件会用缓存里的内容生成一条撤回记录。
之后在会话里发送查询指令，就能看到最近一段时间内被撤回消息的**发送者**和**内容**，图片与表情会一并还原。

仓库地址：<https://github.com/Mizhiawa/astrbot_plugin_anti-recall>

## 安装

**方式一：从链接安装（推荐）**

AstrBot 面板 → 插件管理 → 「从链接安装」→ 填入：

```
https://github.com/Mizhiawa/astrbot_plugin_anti-recall
```

安装完成后插件目录为 `data/plugins/astrbot_plugin_anti_recall`，重启或重载插件即可生效。

**方式二：手动安装**

把本目录放到 AstrBot 的 `data/plugins/` 下，然后在插件管理页重载。

其他说明：

- 配置 NapCat 上报通知事件（默认配置即可；若你改过上报类型，请确保 `notice` 事件正常上报）。
- 无需安装额外依赖。
- `metadata.yaml` 中的 `repo` 字段指向本仓库，因此也可以在面板里使用「检查更新 / 更新插件」。

## 使用

| 指令 | 说明 |
| --- | --- |
| `/防撤回` | 输出当前会话最近被撤回的消息 |
| `/防撤回 群号` | 输出指定群的撤回记录，**仅 AstrBot 管理员可用**，可在任意会话（私聊、别的群）里发 |

- 指令需要 AstrBot 的唤醒前缀（默认 `/`）。如果已把 wake_prefix 设为空，直接发 `防撤回` 即可。
- 群号写法可以是 `1104325443`、`#1104325443`、`群1104325443`；参数里没有群号时会提示用法，不会误查当前会话。
- 不带参数时只包含**当前会话**（同一个群 / 同一私聊）的撤回记录，不会把其他群的记录带到本群。
- 输出为一条消息，文本与图片/表情按原消息顺序混排，示例：

```
最近 10 分钟内共有 2 条消息被撤回：
1. [21:05:40] 张三(123456789)：今晚吃什么
2. [21:07:12] 李四(987654321)：看这个
（紧跟李四撤回的那张图片）
```

管理员指定群查询时会在开头标出群号，方便确认查的是哪个群：

```
群 1104325443 最近 10 分钟内共有 1 条消息被撤回：
1. [21:09:03] 王五(456789123)：这条我发错了
```

## 配置

在插件配置页可调整（见 `_conf_schema.json`）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `window_minutes` | 10 | 查询时间窗口（分钟） |
| `cache_minutes` | 30 | 消息缓存时长（分钟），需不小于查询窗口 |
| `max_items` | 20 | 单次最多输出条数 |
| `images_max_mb` | 200 | 图片缓存体积上限（MB），超过时从最旧的开始删除；单张超过 10MB 的图片直接跳过 |
| `fuzzy_match` | true | 消息 ID 对不上时，用「同发送者 + 撤回前 60 秒内」的最近一条缓存消息兜底 |
| `only_admin` | false | 是否仅 AstrBot 管理员可用（带群号的跨群查询始终只对管理员开放） |
| `debug` | false | 输出诊断日志（收到的消息、撤回命中方式），排查问题时打开 |

## 实现说明与限制

- 依赖 OneBot v11 的撤回通知（`notice.group_recall` / `notice.friend_recall`）与 aiocqhttp 适配器；其他平台不适用。
- 缓存监听器注册在很高的优先级上。AstrBot 中处理器按优先级从大到小执行，且前一个处理器调用 `stop_event()` 后后面的会被跳过；静默监听类插件常会拦掉非唤醒消息，priority 调高才能保证消息先进缓存。
- 缓存保存的是消息段**快照**（文本、图片引用、表情 id 等），不持有 AstrBot 的组件对象——管道后续阶段会改写组件（例如把图片 `url` 改成本地临时路径，事件结束后又会删掉临时文件）。
- 图片的字节由插件自己持有：AstrBot 的预处理阶段会把收到的图片下载到临时目录并把组件的 `url` 改写成本地路径，插件在收到消息时就把这个文件链接/复制（同卷硬链接，跨卷复制）进 `data/plugin_data/astrbot_plugin_anti_recall/images/`。这样即使 AstrBot 的临时目录被它的 `TempDirCleaner` 清掉（默认超过 1GB 时按最旧淘汰），撤回记录里的图片仍能还原。
- 图片缓存随 `cache_minutes` 过期清理，并受 `images_max_mb` 体积上限约束（超限从最旧淘汰）；单张超过 10MB 跳过，同一张图最多尝试物化 2 次。清理在后台线程执行，不会阻塞事件循环；插件卸载时整个目录删除。
- 只有在**机器人收到该消息之后**才谈得上还原内容。机器人离线期间发送并撤回、或缓存时长之外撤回的消息，只会记录到发送者，内容显示为 `[消息未在缓存中，内容不可见]`。
- 消息 ID 精确匹配失败且开启 `fuzzy_match` 时，会退化为「同发送者 + 时间邻近」匹配，极小概率把相邻的一条消息当成被撤回的那条；命中方式会写进插件日志。
- **商城表情（大表情 / `mface`）无法还原**：AstrBot 在接收阶段就丢弃了该消息段，插件拿不到。经典 QQ 表情（`face` 段）可以正常还原。
- 语音、视频、文件只显示占位符（`[语音]`、`[视频]`、`[文件]`），不还原内容。

## 与其他插件的关系

- 缓存监听器是**纯观察者**：不修改事件、不回复、不会调用 `event.stop_event()`，其他插件的处理器照常执行。它注册在最高优先级上，只是为了不被别人的 `stop_event()` 挡在门外。
- 监听器整体包在 try/except 里，**不会向外抛异常**。这点是必须的：AstrBot 中处理器抛异常会对该消息 `stop_event()` 并跳过后续所有插件，而本插件的监听器排在最前面，一旦抛异常就会连累别人（日志里会有 `[防撤回] 缓存消息失败，已忽略该事件`）。
- 图片预下载同时最多 8 个，超出时留给查询时按需下载，避免在消息密集的群里抢带宽。
- 监听器只对 `aiocqhttp` 平台生效，其他平台的事件完全不受影响。
- 注册了全量消息监听器的插件会让 `event.is_wake_up()` 对每条消息都返回 `True`（这是 AstrBot 的设计：只要有插件的过滤器通过就算唤醒）。它不决定 LLM 是否回复（那由 `is_at_or_wake_command` 决定），但如果有插件用 `is_wake_up()` 判断"机器人是否被唤醒"，行为可能与没有本插件时不同。

## 资源占用

单文件、零依赖、无定时器（清理搭在消息处理链上，每 60 秒最多一次），实测：

| 项目 | 实测 |
| --- | --- |
| 每条纯文本消息的缓存开销 | 约 4 µs |
| 每条图文消息的缓存开销 | 约 6 µs |
| 缓存满 2000 条时的内存 | 约 1 MB |
| 图片磁盘占用 | 受 `cache_minutes` 与 `images_max_mb` 双重约束 |

图片是唯一有实际开销的部分，且不额外联网：AstrBot 本来就会把收到的图片下载一遍，插件只是把那份字节链接/复制过来自己保管。

## 排查

如果 `/防撤回` 一直显示「内容不可见」：

1. 打开插件配置里的 `debug`，重发一条消息并撤回，再执行 `/防撤回`。
2. 看插件日志：
   - 有 `缓存消息 chat=... id=...` → 缓存正常，再看撤回那行括号里的命中方式是「精确」「兜底」还是「未命中」，以及 `未命中详情` 中打印的该会话缓存 ID 列表。
   - 完全没有 `缓存消息` → 消息在管道更早的阶段就被拦掉了，检查 AstrBot 的限流、会话状态、内容安全等设置。
